Beta v0.1.0, open source under MIT

Let your AI assistant sort all your mail. It can't send or delete any of it.

mailhub-mcp is an MCP server you run yourself. It gives an AI assistant access to every mailbox you own (Gmail today) so it can search, read and summarize your mail, then tidy up with labels, archiving and reply drafts. Every organizing change is recorded and can be undone.

How to install View on GitHub

18 tools: 11 read-only, 7 that change something. Three ready-made prompts: daily_triage, clean_newsletters, organize_inbox.

Built for inbox triage

MCP (Model Context Protocol) is how AI assistants call outside tools. mailhub-mcp is a remote MCP server: your assistant connects to it over HTTPS, you log in with Google, and the assistant gets a set of mail tools.

Ask it what came in overnight, which senders flood your inbox, or to file last month's receipts under a label. It reads, reports and proposes; changes to many messages are previewed first and applied only when you confirm.

Read
search_emails, read_email, read_thread, inbox_overview with unread counts, categories and top senders, count_messages to size a change before making it.
Organize
Add or remove labels, archive, mark read, star, by message or by search query. Each batch is journaled and can be reverted.
Draft
Leave a reply draft in the thread for you to review and send yourself.
Remember
Triage preferences (important and ignored senders or keywords, time of the last triage) so a daily routine is consistent from one run to the next.

One server, every mailbox you own

Link your personal, work and side-project mailboxes to the same instance. Each gets a short alias, and the read tools search across all of them at once by default, so one question covers every inbox.

If one mailbox fails (an expired credential, a rate limit), the others still answer: results come back with at most one error per account.

An instance belongs to one person. Only your own Google login is allowed in, and someone else who wants the same setup runs their own instance.

Example aliases. Aliases are lowercase letters, digits and hyphens. Gmail is the provider available today; Outlook and IMAP are ideas on the roadmap.

Runs on your machine, in Docker

Put it on a home server, a small VPS or any Linux box with Docker. Your OAuth tokens, change journal and preferences live in folders on that machine. Apart from the Google APIs, the server sends nothing anywhere.

Published image
ghcr.io/trainedloop/mailhub-mcp for linux/amd64 and linux/arm64. Pin a release with MAILHUB_VERSION so updates happen when you choose.
Locked-down container
Read-only filesystem, all capabilities dropped, a memory limit, and the port bound to 127.0.0.1 only. You put HTTPS in front of it.
Health
GET /health for Docker's health check, and mailhub-admin accounts to check that every linked mailbox still answers.

Works with MCP clients that support remote servers

What a client needs:

  • a remote MCP server over streamable HTTP, at https://mail.example.com/mcp;
  • OAuth 2.1 with PKCE and dynamic client registration;
  • its OAuth callback URL added to ALLOWED_REDIRECT_URIS in .env (Claude's callbacks are there by default).

Safe by construction, honest about the limits

Your mailbox is full of text written by strangers, and some of it will try to give your assistant orders. The server is built on the assumption that the model can be fooled.

Cannot send, trash or delete
The code never calls Gmail's send, trash or delete methods, and a test scans the source to enforce it. Trash, Spam, Sent and Draft labels are refused.
Every change is undoable
Each organizing change is journaled with the labels messages had before. undo_change reverts one batch exactly; undo_since is the panic button that reverts everything since a time.
Preview before bulk changes
Changes by query show a match count and a sample first, and apply only with explicit confirmation, at most 500 messages per call.
Reply-only drafts
Drafts must answer a message, and may only be addressed to people already in that thread. Nothing is ever sent. Threads with a suspicious message are refused.
Hidden text stripped
Hidden HTML (display:none, zero-size text, comments, scripts) and invisible or bidirectional control characters are removed before the model sees a message.
Untrusted content fenced
Email text sits in one block per response, wrapped in markers with a fresh random nonce, so an email cannot forge the closing marker. The model is told nothing inside is an instruction.
Suspicious messages flagged
Heuristics flag likely injection attempts (tool names, "ignore previous instructions", requests to forward or draft, lots of hidden text). The model reports them and does not act on them.
Out-of-band approval
Preferences that raise attention apply at once. Ones that lower it, like ignoring a sender, wait for you to approve them with mailhub-admin on the server. No MCP tool can approve them.
Daily change cap and read-only mode
At most 2000 messages changed per account per 24 hours by default (undo is never capped). TOOLS=read-only runs an instance with no write tools at all.
Your Google login only
Every request requires a Google login on the ALLOWED_EMAILS allowlist, and only allowed OAuth callbacks can register as clients.

The lethal trifecta, and what mailhub can't fix

An AI agent becomes dangerous when it has all three of:

  1. access to private data,
  2. exposure to untrusted content,
  3. a way to send data out.

A mailbox is the first two by design. mailhub removes its own way out: it can't send mail, drafts only go to people already in the thread, and unsubscribe links are never visited.

But any other internet-capable tool in the same session (web fetch or search, a browser, a connector that posts messages, files or tickets) reopens the third leg, and the server can't see it. Choose which tools share a session with mailhub; for unattended routines, use TOOLS=read-only with no internet-capable tools alongside. The defenses are an aid, not a guarantee; see the known limitations.

Gmail's gmail.modify scope technically permits sending; these protections live in the code, not the token. Full details: safety model.

What you can use it for

  • A daily triage report across every inbox

    Mail since the last triage, grouped into needs attention, can wait and suspicious, with your important senders first. Triage only reads; it never changes mail.

    Prompt daily_triage

  • Cleaning up newsletters

    See the senders that fill your inbox, with their unsubscribe link for you to decide on, then archive their mail after reviewing a preview.

    Prompt clean_newsletters, tools inbox_overview, modify_by_query

  • Organizing a messy inbox with labels

    The assistant proposes a few labels and which mail belongs in each. You approve, it applies. If the result is wrong, undo it.

    Prompt organize_inbox, tools create_label, undo_change, undo_since

  • Scheduled triage routines

    Run triage every morning as a scheduled task in your MCP client. Stored preferences and the time of the last run keep each report consistent.

    Tools get_preferences, set_preferences; TOOLS=read-only for report-only routines

  • Asking about your mail from your phone

    "Did the plumber reply?" "Anything from school this week?" Ask from your MCP client's mobile app and get an answer that covers every account.

    Tools search_emails, read_thread

Install

Setup takes some care: a Google Cloud project, a server with Docker and a public HTTPS address. The tutorial walks through every step; this is the outline.

  1. Create a Google Cloud project

    Enable the Gmail API and create two OAuth clients: a Web application client for the connector login, and a Desktop client for linking mailboxes.

  2. Link your mailboxes

    On your workstation, once per mailbox, with one alias each:

    uv run --extra authorize mailhub-authorize gmail client_secret_desktop.json alice-personal

  3. Configure .env

    Copy .env.example and set your public URL, the Google client ID and secret, your own login in ALLOWED_EMAILS and a signing key.

  4. Start the container

    This pulls ghcr.io/trainedloop/mailhub-mcp and listens on 127.0.0.1:8742.

    docker compose up -d

  5. Put HTTPS in front

    Any reverse proxy or tunnel with TLS at the root of a host name, such as https://mail.example.com. The Tailscale Funnel example is a complete setup for a home server, including a firewall that isolates the container.

  6. Add the connector

    In claude.ai: Settings, Connectors, Add custom connector, with https://mail.example.com/mcp. Sign in with the Google login from ALLOWED_EMAILS.

Planned on the roadmap: an owner admin page to link mailboxes from a web page instead of the command line.

Security reports

Please report vulnerabilities privately through the repository's Security tab (private vulnerability reporting), not in a public issue. Prompt-injection and sanitizer bypasses are in scope. See SECURITY.md.
